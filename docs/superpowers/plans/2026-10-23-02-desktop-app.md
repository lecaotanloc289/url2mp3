# Plan 2 — Desktop app (Tauri 2, Windows + macOS)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Tauri 2 desktop app over `url2mp3-core`: paste links or a song name, watch a live
queue, change settings; yt-dlp is downloaded and kept up to date by the app; ffmpeg and QuickJS
ship inside it.

**Architecture:** `app/` holds a Vite + TypeScript UI (no framework) and `app/src-tauri`, a
workspace member crate `url2mp3-app`. The Rust side owns settings, the yt-dlp store, the engine
lifecycle and the job table, and forwards core `Event`s to the webview. The UI is a pure reducer
(`state.ts`, unit-tested) plus a small DOM renderer.

**Tech Stack:** Tauri 2.12 (`tauri`, `tauri-plugin-dialog`, `tauri-plugin-opener`,
`tauri-plugin-log`), Vite 8, TypeScript, vitest, `zip`, `sha2`, `reqwest` (rustls).

Spec: `docs/superpowers/specs/2026-10-23-cross-platform-apps-design.md` sections 1–3.
This plan is executed by the same agent that wrote it, in the same session; code lives in the
commits rather than being duplicated here. Each task lists files, contracts, tests and the exact
verification.

## Decisions made while planning

- **Ids across engines.** A new `Engine` is built whenever settings change, and its ids restart
  at 0. Every event sent to the UI carries `gen` (engine generation); the UI keys rows by
  `gen:id`.
- **Cancel** aborts the root task, awaits the handle (so claims are released, see
  `Engine::process` docs), then emits `cancelled { gen, id }` to the UI.
- **Retry** = enqueue the row's original input again as a new root; the old row is removed.
  Failed tracks inside a playlist are retried by retrying the playlist (finished tracks skip).
- **Network failures** of a root are retried once automatically by the UI.
- **Sidecar paths** at runtime: the directory of `current_exe()` (Tauri copies `externalBin`
  next to the main binary, without the target-triple suffix, in dev and in bundles).

### Task 4: yt-dlp store (`ytdlp.rs`)

Contract:

```rust
pub struct Store { root: PathBuf }                    // <app data>/yt-dlp
impl Store {
    pub fn new(root: PathBuf) -> Self;
    pub fn current(&self) -> Option<Installed>;      // reads root/current, checks exe exists
    pub fn install(&self, tag: &str, zip: &[u8], sums: &str) -> Result<Installed>;
    pub fn due_for_check(&self, now: SystemTime) -> bool;   // root/last-check older than 24 h
    pub fn mark_checked(&self, now: SystemTime) -> Result<()>;
}
pub struct Installed { pub version: String, pub exe: PathBuf }
pub const ASSET: &str;                               // "yt-dlp_macos.zip" | "yt-dlp_win.zip"
pub const EXE: &str;                                 // "yt-dlp_macos" | "yt-dlp.exe"
pub async fn latest_tag(client: &Client) -> Result<String>;                 // GitHub API
pub async fn fetch(client: &Client, tag: &str) -> Result<(Vec<u8>, String)>; // zip + SHA2-256SUMS
```

`install`: find `ASSET` in `sums` (`<hex>  <name>` lines), compare with SHA-256 of `zip`, else
error "checksum mismatch"; extract into `root/<tag>.partial` (remove first if present), check
`EXE` exists, rename to `root/<tag>`, write `root/current` via temp file + rename, delete other
version dirs. On unix keep the zip's mode bits and symlinks.

Tests (no network) build zips in memory with the `zip` crate:
- installs, `current()` returns version and exe path, exe is executable (unix);
- wrong checksum → error, `current()` unchanged;
- asset missing from sums → error;
- second install switches `current` and removes the old dir;
- `due_for_check`: true with no file, false right after `mark_checked`, true 25 h later.

  (`cargo run -p url2mp3-app --example ytdlp_install`) installs into the scratchpad and runs
  `<exe> --version`.
- [ ] Commit `feat(app): download, verify and switch yt-dlp versions`.

### Task 6: Jobs and commands (`jobs.rs`, `lib.rs`)

State: `settings: Mutex<Settings>`, `engine: tokio::sync::Mutex<Option<(u32, Arc<Engine>)>>`,
`jobs: Mutex<HashMap<(u32, Id), JoinHandle<()>>>`, `store: Store`, `gen: AtomicU32`.

Commands (all `async`, errors as `String`):
- `get_settings() -> Settings`, `set_settings(s)` → save, drop the cached engine (next enqueue
  builds generation `gen+1`).
- `tools_status() -> { ytdlp: Option<String>, updating: bool }`.
- `update_ytdlp(force: bool) -> String` (version) — `latest_tag`, `fetch`, `install` on a
  blocking thread, `mark_checked`; emits `tools` events `{ phase: "downloading" | "ready" |
  "error", version?, message? }`. Called by the UI at startup with `force: false` (no-op when
  installed and not due).
- `enqueue(inputs: Vec<String>) -> Vec<{gen, id, input}>` — requires an installed yt-dlp; builds
  the engine if needed with `Tools { ytdlp: exe, ffmpeg: sidecar, js_runtime:
  Some("quickjs:<qjs>"), env: [] }`; spawns `engine.clone().process(id, input)`, removes its
  handle when done.
- `cancel(gen, id)` — abort, await, emit `engine` event `{ gen, event: { kind: "cancelled", id } }`.
- `reveal(path)` → `tauri_plugin_opener::reveal_item_in_dir`; `open_url(url)`.
- `read_log() -> String` — last 200 lines of the log file (`tauri-plugin-log`, target LogDir).
- `check_app_update() -> Option<{ version, url }>`.

The sink emits `engine` events `{ gen, event }` with `AppHandle::emit`.

- [ ] Commit `feat(app): job queue and commands`.

### Task 7: UI (`state.ts`, `i18n.ts`, `api.ts`, `main.ts`, `style.css`)

`state.ts`: `Row { key, gen, id, parent?, input?, title, artist?, thumbnail?, status:
'probing'|'downloading'|'fallback'|'converting'|'done'|'exists'|'duplicate'|'failed'|'cancelled',
done, total, path?, message?, network?, retried }`, `Group` for playlists `{ key, title, count,
childKeys }`. `reduce(state, msg)` handles every `kind` plus `enqueued` (creates root rows with
`input`), `cancelled`, `remove`. Tests cover: a single-track happy path, playlist children
attached to their group with done/total counts, skip reasons, failure message kept, cancel,
progress percentage, events for unknown keys ignored.

`i18n.ts`: `vi`/`en` dictionaries with identical keys (test asserts it), `pickLanguage(setting,
navigatorLanguages)`, `hint(message, network)` → key for: network, bot check ("Sign in to
confirm"), unavailable/private, age restricted ("confirm your age"), otherwise generic.

UI: header (title, format select, settings button), textarea + Download button (Ctrl/⌘+Enter),
banner area (yt-dlp first install progress, app update), list of rows/groups (thumbnail,
title, artist, progress bar, status text, actions ✕ / ↻ / 📂), footer "N done · M failed · clear
finished". Settings in a `<dialog>`: output folder (picker), bitrate, tracks at once,
connections, playlist limit, cover, browser cookies (select: none/chrome/edge/firefox/safari/
brave), language (auto/vi/en), yt-dlp version + Update button, Copy log. Light/dark via
